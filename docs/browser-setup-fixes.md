# ブラウザー追加・セットアップ不具合修正（installer-rework、未公開）

## 変更範囲

- ブラウザーの組み合わせではなく、既存の導入先を選んで追加・切り替えます。セッション情報と登録済みNative Hostから導入記録を探します。複数ある場合は利用者が選択し、無人実行では `-InstallRoot` による明示を要求します。
- 導入済み環境ではエンジン準備工程を通しません。API・audio.cpp・モデル・Voice・設定・既存ポートを保持します。ブラウザー用Native Host、Firefox XPIの固定ハッシュ検証と配置、導入案内、保守用ソースのみ追加・更新します。エンジンZIPの再コピーも省きます。
- 同じ登録先のNative Hostは書き換えません。異なる登録先はブラウザー名と新旧パスを表示し、明示的な承諾時だけ現在のユーザーの接続先を切り替えます。PC全体の登録は変更しません。すべての対象を事前確認し、確認中の登録変更も検知します。拒否・無人実行では切り替えません。
- 独立環境の作成・修復／再開は維持します。明示的な修復時には従来どおりヘルパーファイルを更新できます。導入済み環境の設定欠損やポート不一致を、勝手な再インストールで補いません。
- セットアップGUIは起動元PowerShellのプロセスハンドルと起動時刻を確認し、終了を監視します。PID再利用を別の親と誤認しません。通常終了・異常終了時にGUIだけを残しません。中止待ちは最大30秒で画面を閉じますが、この時間上限のためにインストーラーや他の環境を強制終了しません。
- NVIDIA GPUの検出結果とCPU生成の遅さ、GPU名の自己確認方法、既存AI相談文を案内します。CPU/GPU選択ロジック自体は変更していません。GPU完成品の導入だけではGPU動作確認済みとは表示しません。
- 最終保存先とC／選択先ドライブの空き容量を表示し、外部ツールがCドライブを使う可能性を説明します。空き容量不足の対処と相談機能を案内します。保存先選択方式の再設計はしていません。
- 相談文には停止工程・実エラー・GPU・対象ブラウザー・保存先ドライブ・容量・専用ポートを含めます。個人パスは従来の伏せ字処理を維持します。GPU名などの不足情報はコピー後の貼り付け先で記入します。自動送信はしません。
- 一括導入ZIPだけを `これをダウンロードする.zip` に変更し、SHA-256一覧をUTF-8化します。個別エンジンZIPと署名済みXPIの名前・内容は維持します。

## 検証方法

`tests/test_setup_rework.py` は一時フォルダーと模擬レジストリを使用します。実利用中の登録やAPI・エンジンは変更しません。

- Chrome→Firefox、Chrome→両方、Firefox→Chrome、Firefox→両方、両方→両方の導入済み経路を、実際のsetupエントリーポイントで実行します。エンジン準備・Python準備・API再起動などを呼ぶと失敗するスタブを置き、既存ファイルのバイト一致と同じ接続ポートを確認します。XPIはこの経路テストだけ不活性なテスト用ファイルで代替します。
- Chromeのみ／Firefoxのみ／両方のNative Host生成、衝突拒否・承諾・無人実行・PC全体の既存登録・確認中の変更・同一登録の冪等性を確認します。
- GPU成功／失敗の案内、CとDの空き容量、容量不足、AI相談文の情報と伏せ字を確認します。
- 一時的な親プロセスと実際のWindows GUIで、正常終了、エラー終了、親の強制終了、完了通知、キャンセル、キャンセル待ちの30秒上限を確認します。既存／別環境の選択画面も操作して確認します。
- 既存のWindowsインストーラー・修復／再開・配布・ダウンロード・Native Host安全性テストのうち、変更箇所に関連するものを確認します。
- コミット対象だけの検証用ソースで配布一覧を再生成し、一括ZIPの内容とSHA-256、同梱XPIと個別エンジンの固定ハッシュを照合します。作業開始前からある未コミット／未追跡ファイルは配布・コミットに混入させません。

### 実際のターミナルウィンドウを閉じる確認

当初は親プロセス終了の自動テストに留め、実コンソールを閉じる操作を未確認としていました。これは環境制約ではなく検証不足だったため、追加で実施しました。

`tests/test_terminal_close.ps1` により、テスト専用の実コンソール（conhost.exe 10.0.26100.9949＋cmd.exe）から実際の `setup.bat`／`setup.ps1` と製品のGUIを起動しました。準備確認画面も通過し、ファイル配置・取得・登録に入る直前だけテスト用の待機処理に置き換えています。モデル・Voice・実利用環境への変更やツールのインストールはしません。

セットアップ自身が取得したコンソールのウィンドウハンドルを使い、タイトルバーの「×」と同じ `WM_SYSCOMMAND / SC_CLOSE` をそのウィンドウへ送信しました。親PowerShellを `Kill`／`Stop-Process` したテストではありません。物理マウスによるクリックではなく、実在する表示中ウィンドウへの閉じる操作です。

| 状態 | 親セットアップの終了確認 | GUIの終了確認 |
|---|---:|---:|
| 通常の進行中 | 閉じる操作から約14ms | 約335ms |
| 「今回起動した処理を終了しています。」表示・「安全に中止」無効 | 約54ms | 約431ms |

どちらもGUIの30秒上限に頼らず終了しました。無関係なテストプロセスが生存することも確認しています。観測値はポーリングによる目安です。操作コードと判定条件はテストスクリプトに残し、生の結果はテスト専用フォルダーの `results.json` に保存します。途中の試行ではテスト側がコンソールのホストPIDを特定できず中断しましたが、セットアップ自身の `GetConsoleWindow()` で対象を取得するよう補助コードを直した後、上の2状態を確認しました。

- 実コンソールの閉じる操作は上記の2状態で確認済みです。Windows Terminalアプリのタブ閉鎖／ウィンドウ閉鎖、PowerShell 7、すべてのターミナル製品・Windows構成は未確認です。
- `tests/test_download_ui.ps1` の旧対話型通しテストは、新しい接続先選択・保存先確認・GPU案内の画面順に更新しますが、モデル取得を伴う通し実行は今回行いません。画面選択の単体テストと構文確認に限定します。
- GPUの実音声生成、ドライバー不具合、物理的なディスク容量枯渇は再検証しません。表示・分岐・相談文のテストを中心にします。
- 声質安定版の追加方式、GPU対応範囲、完成品、設定は変更しません。`7be42a5` の変更を維持します。GPUビルド、PortableCuda、Visual Studio／CUDA Toolkitの導入は行いません。
- `main`、既存Releaseの編集・差し替え、新規Releaseの公開は行いません。
