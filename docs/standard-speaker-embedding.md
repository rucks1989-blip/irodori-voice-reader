# 通常版でSpeaker Embeddingを使う

この案内は通常版の音声生成用です。声質安定版の処理や拡張機能・署名済みXPIは変更しません。

## 既存のVoice登録画面を使う（推奨）

1. 拡張機能のVoice管理を開き、形式をSpeaker Embeddingにします。
2. 学習済みの `名前.speaker.safetensors` を参照から選択します。通常の `target.safetensors` と混同しないでください。
3. 既存のVoiceを上書きしないよう、新しいVoice IDで登録します。
4. 通常版を選択し、登録したVoiceを明示的に選んで短い文章を生成します。

この操作は元の学習済みファイルを移動・削除せず、登録先の専用フォルダーにコピーします。専用コピーの名前は `speaker.safetensors` です。日本語を含む導入先から音声エンジン用の一時コピーを作る場合も、Speaker Embeddingの種類と内容を維持します。WAVに改名・変換しません。

## 外部の学習済みフォルダーをコピーせず使う

自動検出の追加先は、導入先の **`irodori-api/config/voice_sources.json`** に設定できます。既存の `voices.json` を書き換える必要はありません。初回は同じフォルダーの `voice_sources.example.json` を別名コピーして作成してください。既に設定ファイルがある場合は上書きしないでください。

```json
{
  "speaker_embedding_dirs": ["../saved-speaker-embeddings"]
}
```

- 相対パスは `irodori-api` フォルダーを基準に解決します。上の例は `irodori-api` と同じ階層の `saved-speaker-embeddings` です。カレントディレクトリーに依存しません。
- 任意の保存先の絶対パスも指定できます。WindowsのバックスラッシュはJSON内では `\\` と記入します。パスはPCごとに指定し、特定のドライブやフォルダーを全利用者向けに固定しません。
- 指定フォルダー直下の `*.speaker.safetensors` のみを読み取ります。通常の `.safetensors`、WAV、モデルは自動で取り込みません。元ファイルと学習済みデータは変更しません。
- ファイル名からVoice IDを作成します。既存の明示的な登録と同じIDがあっても、既存登録を別ファイルに置き換えません。
- `disabled_auto_voices` に登録されたVoiceは従来どおり自動検出から除外します。
- Voice一覧を更新すると設定を再読込します。この外部フォルダー設定は通常版のみで使用します。

### 日本語を含む一時保存先について

音声エンジン用の小さな一時コピーは、まず通常の一時フォルダーを使用します。導入先内の一時フォルダーが日本語を含む場合は、`LOCALAPPDATA` 配下のユーザー専用 `IrodoriVoiceReader/StandardReferenceCache` を使用します。モデルや元の学習済みファイルを移動する処理ではありません。

一時フォルダーとユーザーフォルダーの両方が非ASCIIの場合など、必要があれば `voice_sources.json` の `reference_cache_dir` に、書き込み可能でパス全体が英数字の専用フォルダーを指定してください。保存先はPCごとに選びます。明示的に指定した場所が使えない場合、別の場所へ勝手に切り替えず、設定エラーを表示します。

## エラー時

- 存在しないVoice IDは「voiceが見つかりません」として拒否します。
- 登録はあるがファイルがない場合は、Voice IDと実際の参照先を含むエラーになります。別のVoiceや同じIDの自動検出ファイルへ黙って切り替えません。
- 不正なSpeaker Embeddingの拡張子と、存在しないSpeaker Embeddingは区別して案内します。Speaker Embeddingを「参照WAVが見つからない」と誤表示しません。
- 保存先フォルダーが見つからない場合は、そのフォルダーの設定を確認してください。別ドライブのデータを勝手に探したり、学習済みデータを削除して復旧したりしません。

既存のVoice IDを別の声に結び直す自動移行は行いません。拡張機能の初期Voice表示の修正も今回の対象外です。
