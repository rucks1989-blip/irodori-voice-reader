## 音質安定版は非推奨！作るまでに時間かかる可能性あるから通常版だけの方が絶対に良い！。迷わず通常版だけ選んで！上にあるzipダウンロードしてsetup.bat押すだけ

AIチャットの文章をIrodori-TTSのキャラクター音声で読み上げるWindows x64向けソフトです。
Chrome拡張1.2.26とMozilla署名済みFirefox拡張1.2.27を同梱しています。
初めて利用する方は `これをダウンロードする.zip` をダウンロードしてください。ZIPをすべて展開し、`setup.bat` をダブルクリックするとセットアップが始まります。
GitHub Releaseの「Source code」ではなく、この一括導入ZIPを選んでください。個別エンジンZIPを追加でダウンロードする必要はありません。必要な取得はセットアップが案内します。



## 導入方法。基本的にはsetup.bat押してクローム版かfirefox版か両方か選んであとは勝手にダウンロード。途中保存場所とか聞かれるけどその時は自由に選んで！声質安定版を作るは時間かかりすぎるので選ばないように。


1. 配布一式を展開し、フォルダー内の `setup.bat` を実行します。BATだけ移動しないでください。
   ダウンロードに失敗しても、その場で何度でも再試行できます。手動取得したファイル・ZIP・展開済みフォルダーは好きな保存先から参照できます。[取得・復旧の詳しい案内](docs/downloads-and-recovery.md)
2. Chromeのみ／Firefoxのみ／両方を選びます。
3. 既存環境があれば、ブラウザーの接続先として選べます。ChromeからFirefox、FirefoxからChrome、両方への変更は設定の追加として扱い、API・audio.cpp・モデル・Voice・設定・ポートを再利用します。再取得・再ビルドはしません。新しい別環境を作る選択も可能です。



   初回は保存先を選びます。「参照」で別のフォルダーを選べます。最低5GBの空き容量を確認し、その場所に `chrome-` などの専用フォルダーを作成します。モデル・専用Python環境・エンジン・ダウンロード・一時ファイルもこの保存先に置きます。
   導入直前に最終的な保存先、Cドライブと選択先ドライブの空き容量を表示します。外部のPythonやMicrosoft実行環境のインストールではCドライブも使用する場合があります。容量不足なら表示された保存先の空きを確保するか、初回導入では別の保存先を選んでください。既存モデルやVoiceを勝手に削除しないでください。
   GPU声質安定版まで追加する場合は、展開キャッシュや通常版の保持分も含めて15GB程度の空きを推奨します。任意ビルドにはさらに開発ツール用の容量が必要です。
4. 接続する環境とポートを確認します。Native Host登録が別の環境を指す場合は、問題のブラウザー・既存の登録先・今回の登録先を表示します。明示的に承諾した場合だけ現在のユーザーの接続先を切り替えます。拒否すれば既存登録を保持して停止します。独立環境そのものは削除しません。
5. 専用Python環境、ハッシュ検証済みモデル、完成済みエンジンを準備します。既存モデルを選んだ場合も新しい導入先へコピーします。
6. 完成品が不足する場合は「対応完成品を用意して再開／このPC向けにビルド／中止」を選びます。ビルドは任意です。自動で開始したり、CPUへ切り替えたりしません。
7. 利用権限のある参照WAVを登録し、通常・声質安定プロファイルの音声生成を確認します。WAV生成成功と声質安定アルゴリズムの有効性確認は別です。声質安定版を導入しなかった場合は、セットアップ完了時にその旨を画面・コンソール・`docs/finish.html` に表示します。
8. 導入先の `docs/finish.html` に従い、最後に拡張を手動追加します。

途中の「安全に中止」で今回起動した処理を終了します。セットアップの親プロセスが終了すれば確認画面も終了します。中止待ちの画面は最大30秒で閉じますが、画面を閉じるためだけに実行中のファイル操作を強制終了しません。再実行時に既存環境を選ぶと再開・ブラウザー追加ができます。修復が必要な場合だけ `setup.bat -Repair` を使用します。
既存環境のプロセス名による一括終了は行いません。新しい別環境は `setup.bat -NewEnvironment` で作成します。選択した保存先は `%LOCALAPPDATA%\IrodoriVoiceReader\Installer\location.json` に記録し、次回の既定値にします。小さなセッション情報と確認画面だけをこのフォルダーに残し、導入本体・状態・ログ・ダウンロード・一時ファイルは選択した保存先へ置きます。
複数の独立環境がある場合は接続先を選んでください。一覧にない導入済み環境は `setup.bat -InstallRoot "既存環境の保存先" -Browsers both` で指定できます。ブラウザー追加では `-Repair` や `-NewEnvironment` は不要です。

### GPU検出と困ったときの相談　GPU検出する時エラーメッセージっぽくなってるけど正常です、ポンコツgptのせいです！
<img width="1461" height="700" alt="image" src="https://github.com/user-attachments/assets/94539a8a-eaa2-4b81-84eb-c559b703579f" />

NVIDIA GPUを検出すると「NVIDIA GPUを検出しました。GPU対応版の音声エンジンを準備します。」と表示します。導入だけで実際のGPU動作確認済みとはしません。
検出できない場合、自動選択ではCPU版を使い、生成に長い時間がかかる場合があります。NVIDIA搭載PCでもドライバーなどにより検出できないことがあります。既存のCPU/GPU選択ロジックや明示指定は変更していません。
原因が分からない場合や容量不足・Native Host衝突では、`AI-support.bat` の既存機能で相談文を確認・コピーし、ChatGPTに貼り付けてください。自動送信はしません。停止工程・実際のエラー・GPU情報・対象ブラウザー・保存先情報を含みます（個人パスは伏せ字）。GPU名が不明ならタスク マネージャーの「パフォーマンス」→「GPU」などで確認し、相談文に手入力してください。

`chrome://extensions/` → デベロッパーモード → パッケージ化されていない拡張機能を読み込む → 案内された導入先の `chrome-extension` を選択します。

### Firefoxへの最後の追加

1. Firefoxのアドレス欄に `about:addons` と入力します。
2. 歯車ボタン →「ファイルからアドオンをインストール」を選びます。
3. 完了案内に表示されたインストール先の `IrodoriVoiceReader-Firefox-1.2.27-signed.xpi` を選び、「追加」を許可します。

XPIは展開・編集しません。署名設定の無効化や開発者版Firefoxは不要です。同じFirefoxプロファイルの同じ拡張IDへの更新では既存設定を保持します。既に利用中の拡張を削除・初期化する必要はありません。

### 声質安定版を後から追加する（やりたい人だけ！非推奨）



通常版のみで導入しても問題ありません。インストール先の **「声質安定版追加する.bat」をダブルクリックすると後から追加できます**。
先に拡張の操作で音声エンジンを停止してください。配布ZIP側ではなく、セットアップ完了画面に表示されたインストール先のBATを使います。
既存の `setup.bat -Repair` と同じ修復処理を使用し、Voice・モデル・ユーザー設定は保持します。
CPU方式は同梱の声質安定版完成品を使用します。GPU方式は既存のGPU自動検出を使い、対応する声質安定版完成品を優先します。対応完成品がなければ、既存の選択画面から完成品の指定・任意ビルド・中止を選べます。任意ビルドには対応CUDA ToolkitとC++ビルド環境が必要です。上流の通常版完成品は声質安定版の代わりにはなりません。確認なくビルドしたり、CPU方式へ変更したりしません。
追加後は拡張のエンジン選択で「通常版」と「声質安定版」を切り替えられます。元の通常版実行ファイルも保持します。
GPU声質安定版の同梱完成品は **CUDA sm86** 向けです。特定の製品名に固定せず、検出されたGPU世代との一致で選びます。他のGPU世代は同梱完成品での動作確認済みとはしていません。既存の任意ビルドでは、そのPCで検出した世代向けに作成します。

## 完成品と任意ビルドの違い

GPU推論とソースのコンパイルは別工程です。対応GPU完成品を使えばCUDA Toolkit・Visual Studio Build Tools・CMakeは不要です。NVIDIAドライバーと必要な実行時ライブラリは必要です。



## 既存機能と設定

ChatGPT,Gemini,Muse回答検出、自動・手動読み上げ、キャラクター／ナレーション振り分け、話者タグ・別名・Voice ID、会話括弧、Voice準備確認のmain修正を維持しています。新しい導入先の接続情報は生成ファイルへ保存し、利用者向けの設定項目は増やしていません。

### シンプルな使い方説明
詳細タブからwavを登録する→基本1つのwavで全部読む。複数wavとか登録してたらナレーションをオンにして地の文をナレーション、「」とかの文章を任意のwavで生成可能。
あとは例えばルナ、テラ、ソルというwavの表示名を登録してた場合、初期設定だと【ルナ】「こんにちは」とかにすると指定したルナのwavが「こんにちは」だけ読む。【ルナ】は読まない。
なのでナレーションと組み合わせると
今日放課後、生徒会で熱い議論が交わされていた【ルナ】「ちょっと、なんでソルは成績いいのにポンコツなの？言われたことすらしない、完了しましたとか言って完了してないじゃない！」【ソル】「私を使うのにはお金がかかるからよ。ちゃんと指示しないとまともに動かないわ。私は安い女じゃないの、ちゃんと攻略しなさい」と謎の発言をソルがしていた。するとテラが【テラ】「私っていっつも存在忘れられるんだよね・・・。私の存在って一体・・・。」そうテラは嘆いていた
みたいな感じの文章だとルナ、テラ、ソル、そしてナレーションに指定していたボイスが地の文を読む形になります。


### 話者タグの区切り記号
Chrome・Firefoxの詳細設定／サイドバーで「話者タグの開始記号」「話者タグの終了記号」を変更できます。既定は `【` と `】` です。`[` と `]`、`＜` と `＞`、`{` と `}`、複数文字も指定できます。空欄・改行を含む設定は既定の組へ戻ります。
内側の登録名・別名・Voice IDを従来どおり解決します。「会話として扱う括弧」とは独立した設定です。例えばタグを `[]`、会話括弧を `「」` と `（）` にすると、`[クリス]（一）（二）地の文` はナレーションON・タグ優先ONで「一」「二」をクリスVoice、地の文をナレーションVoiceへ送ります。既存のVoice・モデル・キャラクター設定の初期化は不要です。
設定同期は同じブラウザプロファイル内の詳細設定とサイドバー間です。ChromeとFirefox間の設定移動は設定のエクスポート／インポートを使用します。
